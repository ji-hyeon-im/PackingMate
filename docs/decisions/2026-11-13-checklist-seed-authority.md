# 체크리스트 시드 데이터의 소유권과 적용 방식

- 결정일: 2026-11-13
- 상태: 적용

## 결정

`checklist_item`, `checklist_item_alias`, `checklist_item_required_tag`, `checklist_item_exclude_tag`, `country_power_supply`, `country_power_plug`는 SQL 시드가 원본인 기준 데이터 테이블로 취급한다. Spring SQL 초기화가 시작할 때마다 `data.sql`을 실행하므로, 시드는 이 여섯 테이블의 전체 상태를 트랜잭션 안에서 동기화한다. 별칭·태그 관계를 먼저 지운 뒤 기본 항목을 지우고, 현재 시드의 전체 행을 다시 넣는다. 따라서 시드에서 제거된 행도 다음 시작 때 정리된다.

## 이유와 영향

현재 데이터는 고정된 기준 준비물 목록이며 사용자 여행 입력이나 체크 상태는 브라우저에만 저장된다. 시드를 원본으로 정하면 추가·수정·삭제가 동일한 방식으로 반영되어 과거 태그가 DB에 남는 문제를 막을 수 있다.

앱 시작 때마다 해당 여섯 테이블의 직접 수정은 덮어쓰이거나 제거된다. 이 테이블에 운영자 편집이나 사용자 생성 데이터를 넣지 않는다. 해당 요구가 생기면 소유 구분을 추가하거나 버전 관리되는 데이터 마이그레이션으로 전환한 뒤 시드 동기화 범위를 조정해야 한다.

## 근거

외부 표준이 아니라 현재 MVP의 고정 기준 데이터와 `spring.sql.init.mode: always` 설정을 바탕으로 한 자체 설계 결정이다. DB 직접 수정이 보존되지 않는 동작은 README와 이 결정 기록에 명시한다.
